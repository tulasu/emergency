# Промпт для генерации черновика сценария

Скормите это модели в чистом чате. Подставьте строку билета в блок
`ВЫЗОВ`. Ответ сохраните как `draft_<id>.json`.

Модель заполняет только факты, перефразировки и реплики. Правила
дизамбигуации и пороги она **не пишет** — их выводит `scenario_builder.py`.

---

## Текст промпта

````
Ты готовишь учебный сценарий для тренажёра операторов службы «112».
В тренажёре роль заявителя играет программа: она хранит набор фактов и
выдаёт нужный факт, когда обучающийся о нём спросил.

ВЫЗОВ (строка из экзаменационного билета, дословно):
<<<
Ситуация: [ВСТАВИТЬ ОПИСАНИЕ СИТУАЦИИ]
Адрес: [ВСТАВИТЬ АДРЕС ЦЕЛИКОМ, ВКЛЮЧАЯ СКОБКИ]
>>>

Важно про скобки: то, что в строке билета указано в скобках или курсивом,
заявитель сам не называет. Он говорит это только если оператор задал
уточняющий вопрос. Такие сведения оформляй отдельными фактами.

Разложи вызов на факты и верни ОДИН JSON-объект по схеме ниже. Никакого
текста до или после JSON.

{
  "scenario_id": "bilet<NN>_call<NN>_<короткий_латинский_слаг>",
  "meta": {
    "ситуация": "<строка билета>",
    "адрес_эталон": "<полный уточнённый адрес>",
    "итоговый_тип": "<предполагаемый тип происшествия>"
  },
  "facts": [
    {
      "key": "короткий_ключ_на_русском",
      "group": "имя_группы",
      "value_numbers": [13],
      "requires": [],
      "paraphrases": ["...", "..."],
      "replies": {
        "ask": "...",
        "repeat": "...",
        "confirm": "...",
        "correct": "..."
      }
    }
  ],
  "opening": "<первая фраза заявителя, 1-2 предложения, только то, что он говорит сам без расспросов>",
  "critical": ["<4-6 ключей фактов, обязательных для карточки>"],
  "profile": "calm"
}

Правила заполнения:

1. ФАКТЫ. Один факт — одна единица сведений, которую оператор обязан
   занести в карточку: адрес, ориентир, этаж, этажность, доступ,
   пострадавшие, приметы транспорта, ФИО, телефон, признаки происшествия.
   Обычно получается от 6 до 12 фактов. Не объединяй два сведения в один
   факт.

2. GROUP. Факты, о которых спрашивают похожими словами, клади в одну
   группу: этаж возгорания и этажность дома — группа «этажи»; марка и
   госномер машины — группа «авто». Факт без близких соседей получает
   собственную группу.

   ВНУТРИ ОДНОЙ ГРУППЫ перефразировки разных фактов обязаны различаться
   хотя бы одним содержательным словом. Если у двух фактов группы все
   слова общие — переформулируй, иначе сценарий не соберётся.

3. PARAPHRASES. От 8 до 12 способов спросить об этом факте. Обязательно
   разной длины: развёрнутый вопрос, короткий, одно слово. Разговорные
   обороты приветствуются. Не вставляй сюда числа и значения — только
   вопросы.

4. REPLIES. Реплики от лица заявителя, в его эмоциональном состоянии:
   - ask — первый ответ на вопрос;
   - repeat — ответ, когда спросили повторно (с досадой, короче);
   - confirm — ответ на переспрос «верно?» (просто подтверждение);
   - correct — возражение, если оператор назвал НЕВЕРНОЕ значение.
     Обязателен для всех фактов с числами.
   Поля assert НЕ пиши: движок его не использует.

5. VALUE_NUMBERS. Числа, которые содержит значение факта: этаж, номер
   дома, срок, возраст. Нужны, чтобы заявитель мог поправить оператора.
   Если чисел нет — пустой список.

6. REQUIRES. Ключи фактов, без которых этот факт не выдаётся. Например,
   уточнённый адрес выдаётся только после того, как спросили про
   ориентиры. Обычно пустой список.

7. Не выдумывай сведений, которых нет в строке билета. Если заявитель
   чего-то не знает, так и напиши в replies: «не знаю», «не видно».

8. АДРЕС НЕ ДРОБИ: максимум 3 адресных факта на сценарий (например,
   «место», «ориентир», «уточнённый адрес»). Пять-шесть фактов вида
   «город/улица/дом/строение» глушат друг друга при распознавании:
   оператор спрашивает «где это?» один раз, а отвечают все сразу.

9. ПОЖАРЫ И ДТП: всегда заводи факт «доступ» (проезд свободен ли,
   шлагбаум, кто встретит службы). Оператор спрашивает об этом в каждом
   втором разговоре; без факта эти вопросы уходят в «не знаю».

10. OPENING — только то, что заявитель говорит сам в первой фразе.
    Сведений из скобок там быть не должно.

11. CRITICAL — только существующие ключи facts (проверяется автоматически,
    несуществующий ключ роняет сборку).

Верни только JSON.
````

---

## Что проверить в ответе модели

Перед сборкой пробегите глазами:

- **Скобки из билета стали отдельными фактами.** Это главный смысл
  задания: уточнённый адрес, этажность, газификация не должны лежать в
  первом же ответе заявителя.
- **Внутри группы есть различающие слова.** Если у двух фактов группы
  перефразировки совпадают по словарю, билдер скажет об этом явно.
- **Реплики звучат как человек, а не как справка.** «На тринадцатом,
  балкон весь в огне» лучше, чем «Этаж возгорания — тринадцатый».
- **`correct` есть у всех числовых фактов.** Без него заявитель молча
  согласится с ошибкой оператора.
