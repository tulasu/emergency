# Как запустить конвейер

Инструкция от пустой папки до готового сценария с измеренным покрытием.
Каждый шаг: что делать, зачем, и на что смотреть в выводе.

---

## Шаг 0. Подготовка

Положите в одну папку:

```
dialog_engine.py          движок: нормализация, матчинг, речевые акты
scenario_builder.py       сборка сценария из черновика + самопроверка
run_scenario.py           запуск любого сценария и слепая оценка
suite.py                  регрессионный стенд
drafts.json               черновики сценариев (вход)
built.json                собранные сценарии (выход, создаётся автоматически)
PROMPT_scenario_draft.md  промпт №1: черновик сценария
PROMPT_blind_operator.md  промпт №2: слепые реплики оператора
```

Проверка, что всё на месте:

```bash
python3 suite.py built.json
```

Должно закончиться строкой `неверно выданный факт: 0 (0.0%)`. Если да —
окружение рабочее, зависимостей никаких не нужно, только Python 3.10+.

---

## Шаг 1. Сделать черновик сценария

**Что делаете.** Открываете `PROMPT_scenario_draft.md`, копируете текст
промпта в чистый чат любой сильной модели, подставляете в блок `ВЫЗОВ`
строку из билета дословно — вместе со скобками.

Пример подстановки из билета 4:

```
Ситуация: Горит балкон и два окна рядом на 13-м этаже, открытое пламя,
пострадавших не видят, наблюдают с улицы, Сидорова Анна Викторовна
(этажность - 14, дом газифицирован)
Адрес: Москва, ул. Грина, № дома неизвестен, в данном доме находится
библиотека № 193 (ул. Грина, дом 11)
```

**Зачем.** Модель раскладывает вызов на факты и придумывает 8–12 способов
спросить о каждом. Руками это писать долго и получается однообразно:
человек придумывает три формулировки и выдыхается, а нужно десять.

**Что получите.** JSON-объект. Сохраните как `draft_bilet04.json`.

**На что смотреть.** Сведения из скобок обязаны стать отдельными фактами.
Если «этажность 14» оказалась внутри первого ответа заявителя — переделайте,
иначе исчезает главная учебная механика: обучающийся должен эти сведения
*добыть*, а не получить даром.

---

## Шаг 2. Собрать сценарий

**Что делаете.**

```bash
python3 scenario_builder.py draft_bilet04.json -o built.json
```

Для нескольких сценариев сложите черновики в один JSON-массив:

```bash
python3 scenario_builder.py drafts.json -o built.json
```

**Зачем.** Билдер достраивает то, что модель не пишет: пороги,
недостающие реплики, и главное — **правила различения фактов внутри
группы**. Раньше мы писали их руками регулярками, и именно там сидели
четыре бага из девяти. Теперь правило выводится из банка перефразировок:
различающей считается основа, которая есть у одного факта группы и с
которой не начинается ни одно слово соседних.

**Что увидите.**

```
=== bilet04_call01_fire_grina
  фактов: 9, перефразировок: 67
  самопроверка: 67 ок, 0 промахов
  групп: 7, правил выведено для: ['этажи', 'газ']
```

**На что смотреть.** Строка «самопроверка». Билдер прогоняет каждую
перефразировку через матчер и требует, чтобы она попала в свой же факт.
Пока там не ноль промахов, сценарий недоделан.

Типичные сообщения и что с ними делать:

| Сообщение | Причина | Что делать |
|---|---|---|
| `«X» -> ambiguous` | внутри группы нет различающих слов | переформулировать перефразировки одного из фактов |
| `«X» -> другой_факт` | слово-ключ встречается у соседа | убрать чужое ключевое слово из банка |
| `! key: нет ни одного различающего слова` | два факта группы описаны одинаково | развести формулировки или объединить факты |
| `! key: всего N перефразировок` | меньше пяти | дописать вручную или перегенерировать |

Правьте **черновик**, а не `built.json`. Собранный файл перезаписывается
на каждом прогоне.

## Шаг 3. Прогнать регрессию

**Что делаете.**

```bash
python3 suite.py built.json
```

**Зачем.** Это защита от того, чтобы новый сценарий сломал старые.
Стенд проверяет три вещи: тяжёлые пары внутри сценария, вопросы вне
сценария и кросс-утечки между сценариями.

**Что увидите.**

```
1. HARD NEGATIVES : 34/35 правильно | неверный факт 0 | переспрос 1
2. ВНЕ СЦЕНАРИЯ   : 48/48 правильно | неверный факт 0 | переспрос 0
3. КРОСС-УТЕЧКИ   : 8/8 правильно | неверный факт 0 | переспрос 0
ВСЕГО 91 проверок | неверно выданный факт: 0 (0.0%)
```

**На что смотреть.** Только на последнюю строку. Ноль неверно выданных
фактов — блокирующее условие. Переспросы не блокируют ничего: заявитель,
который переспросил, ведёт себя как человек. Заявитель, который выдал
неправильный этаж, портит занятие и учит плохому.

Добавляя сценарий, допишите для него блок в `HARD` внутри `suite.py`:
пары «фраза → ожидаемый факт» для слотов, которые легко спутать.

## Шаг 4. Поговорить с заявителем руками

**Что делаете.**

```bash
python3 run_scenario.py built.json                 # список сценариев
python3 run_scenario.py built.json -s bilet04      # диалог
```

Печатаете реплики оператора, видите ответы заявителя и в квадратных
скобках — какой факт сработал и каким речевым актом.

**Зачем.** Автотесты не ловят неестественность. Здесь вы слышите, звучит
ли заявитель как человек, не повторяется ли он дословно, реагирует ли на
подтверждения и на ошибочное резюме.

**На что смотреть.** Пометка `← ПОПРАВИЛ` должна появляться, когда вы
называете неверное число. Скажите «значит на четырнадцатом горит» — если
заявитель согласился, у факта не заполнены `value_numbers` или `correct`.

## Шаг 5. Слепая генерация реплик

**Что делаете.** Открываете `PROMPT_blind_operator.md`, копируете промпт
в **новый чистый чат**, подставляете описание ситуации из билета. Ответ
сохраняете построчно в `phrases_bilet04.txt`.

**Зачем.** Это единственный способ узнать реальное покрытие. Перефразировки
писала та же модель, что и сценарий, поэтому проверять на них — значит
проверять систему на её собственных ответах.

**Критично.** Модель не должна видеть ни `built.json`, ни списка фактов.
Чистый чат, никакой истории. Иначе тест перестаёт быть слепым и покажет
красивую, но ложную цифру.

## Шаг 6. Измерить покрытие

**Что делаете.**

```bash
python3 run_scenario.py built.json -s bilet04 -f phrases_bilet04.txt --blind
```

**Что увидите.**

```
фраз: 60 | распознано: 31 (52%) | неоднозначно: 4 | не покрыто: 25

попадания по фактам:
    5  этаж_возгорания
    0  ориентир            ← НИ ОДНОГО ПОПАДАНИЯ

неоднозначные (нужны различающие слова):
  · Люди в подъезде остались?

НЕ ПОКРЫТО — кандидаты в банк перефразировок:
  · Что у вас случилось?
  · Дым сильный?
```

**Как читать.**

**Процент распознанного** — общий индикатор. 50% на первом прогоне
нормально. Растёт с каждой итерацией.

**Факт без единого попадания** — самое тревожное. Люди спрашивают об этом
совсем другими словами, чем вы придумали. Такой факт переписывается целиком.

**Неоднозначные** — самое ценное. Границы между слотами размыты. Каждую
такую фразу заносите в `HARD` в `suite.py` с правильным ответом: это готовый
регрессионный тест.

**Не покрыто** — сырьё. Разложите на три кучи:
- про существующие факты → дописать в `paraphrases` черновика;
- про факты, которых нет → завести факт (или ответ «не знаю»);
- не по делу → оставить, переспрос тут правильная реакция.

## Шаг 7. Замкнуть цикл

```bash
# правите draft_*.json по результатам шага 6, затем:
python3 scenario_builder.py drafts.json -o built.json   # пересобрать
python3 suite.py built.json                             # регрессия
python3 run_scenario.py built.json -s bilet04 -f phrases2.txt --blind
```

**Важно.** На каждой итерации берите **новую генерацию** от модели по
промпту №2. Если гонять один и тот же файл фраз, вы просто выучите его
наизусть, а покрытие на живых людях не изменится.

Обычно хватает трёх итераций на сценарий. Признак остановки: процент
распознанного перестал расти, а список «не покрыто» состоит из вопросов
не по делу.

## Порядок работы на несколько сценариев

1. Выберите 8–12 вызовов из билетов, покрывающих разные группы
   происшествий: пожар, ДТП, медицина, ЖКХ, правопорядок. Не берите 96 —
   глубина проработки важнее объёма.
2. Прогоните шаги 1–2 для всех сразу, сложив черновики в массив.
3. Шаги 5–7 делайте по одному сценарию: слепой тест на каждый свой.
4. После каждого сценария — `suite.py` целиком, а не только новый блок.

## Что нельзя нарушать

- **Правите черновик, не `built.json`.** Собранный файл перезаписывается.
- **Ноль неверно выданных фактов.** Любая правка, роняющая эту строку,
  откатывается, какой бы полезной ни казалась.
- **Слепой чат для промпта №2.** Загрязнённый контекст обесценивает
  измерение.
- **Стенд зелёный перед каждым коммитом.** Иначе правка за час до
  дедлайна станет лотереей.
