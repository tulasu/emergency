# dispatcher — ядро заявителя для тренажёра оператора 112

Оператор задаёт вопрос, заявитель отвечает фактом из билета. Ответы конечны
и известны заранее, поэтому задача не генеративная, а классификационная:
реплику надо отнести к известному сведению либо честно отказать.

Дальше ядро встаёт в SIP-конвейер `VAD → STT → понимание → TTS`, поэтому
всё считается офлайн и за единицы миллисекунд.

## Чем отличается от старого ядра

Классификация идёт не по фактам сценария, а по **общей онтологии слотов**.

```
реплика → слот (addr.street, victim.count, caller.phone …)
        → факт текущего сценария, привязанный к этому слоту
        → такого факта нет → «не знаю», и это правильный ответ
```

810 фактов из 96 сценариев разложены по 88 слотам. Формулировки принадлежат
слоту, а не факту, поэтому банк один на весь корпус: за слот «адрес»
проголосовали десятки сценариев, и медиана формулировок на слот — 28 против
9, которые автор писал руками на каждый факт.

Практический смысл — расширение. Новая ситуация получает формулировки даром:
автор пишет только содержание.

## Устройство

```
data/ontology/slots.yaml  онтология: слоты, алиасы старых ключей, замещения
data/scenarios/*.json     97 сценариев в каноническом формате (см. ниже)
data/blind/*.txt          102 слепых набора, 6105 реплик оператора

dispatcher/types.py       типы, которыми обмениваются слои
dispatcher/data/          онтология, загрузка, сборка, инструменты автора
dispatcher/nlu/           нормализация, правила, банк, векторы, каскад
dispatcher/dialog/        состояние звонка, политика, речь
dispatcher/session.py     потоковый и текстовый вход поверх одного кода
bench/                    измерения
```

## Каскад понимания

Три слоя, каждый следующий дороже и вызывается реже:

| слой | что делает | цена |
| --- | --- | --- |
| правила | речевой акт, числа, уточнение «а корпус?» | 0.03 мс |
| банк | лексика, сплавленная с векторами | 0.4 мс без модели, 9 мс со сплавом |
| арбитр | локальная модель выбирает из пяти кандидатов | **выключен, см. ниже** |

Главный признак уверенности — не оценка лидера, а **разрыв до второго
кандидата, ведущего к другому ответу**. Абсолютная оценка зависит от
энкодера и от того, сколько формулировок накопил слот; разрыв не зависит ни
от того, ни от другого. На корпусе разрыв держит долю ложных ответов на 1.7%,
тогда как абсолютный порог не опускается ниже 6% ни в одной точке.

Оценка считается по всем 88 слотам, а не только по слотам сценария: иначе
не отличить «не расслышала» от «поняла вопрос, но такого заявитель знать не
может». Это разные ответы.

### Фора населённого слота

У слота «адрес» 466 формулировок, у «погоды» — пять. Максимум косинуса при
таком перекосе почти всегда достаётся населённому: попыток больше. Измеренный
фон подтверждает — `addr.full` 0.504 против `env.weather` 0.195, то есть треть
балла форы на каждом запросе.

Банк вычитает фон слота: его среднюю оценку на посторонних репликах.

| | всего | слоты с ≤15 формулировками |
| --- | --- | --- |
| без вычета | 73.9% | **8.6%** |
| с вычетом | **76.0%** | **13.2%** |

Растёт и то, и другое — в отличие от ограничения банка сверху, которое бедным
слотам помогает, а общему качеству вредит (73.7% → 63.7% при пределе в 12
формулировок).

Восемь с половиной процентов на бедных слотах — цифра, которую стоит помнить,
когда читаешь обещание «новая ситуация получает формулировки даром». Даром их
получают частые слоты. Новый слот, которому автор написал пять затравок,
находится в 15–18% случаев (`bench/newslot.py`), и дообучение это чинит слабо
(+2.8 пункта).

После вычета фона шкала сжимается примерно вдесятеро: оценка лидера может
быть отрицательной, разрывы измеряются сотыми. Все пороги пришлось
пересчитать — и **не по формулировкам корпуса, а по слепым наборам**: на них
шкала другая, проверено ценой обвала сквозного прогона с 53.9% до 32.2%.

### Два слова, которые нельзя выбрасывать

Стоп-лист — самое опасное место в нормализации. Дважды оказалось, что
выброшенное как «служебное» слово несло весь смысл.

**Вопросительные слова.** «Что случилось» и «где случилось» после выкидывания
«что» и «где» становятся одной репликой, а это разные слоты. Возврат:
**+5.5 пункта**.

**Местоимения лица.** «Как вас зовут» и «как её зовут» отличаются только ими,
а это ФИО заявителя против ФИО пострадавшего — самая частая ошибка корпуса.
Возврат: **+1.7 пункта**, и конкретная путаница упала с 59 случаев до 47.
Мало вернуть их в стоп-листе: «вы», «он», «их» короче трёх букв, и фильтр
длины съедал их следом.

Оба множества исключаются из `topical_lemmas`, по которым отличается
«не расслышала» от «не знаю»: у реплики «а вы что?» темы по-прежнему нет.

### Дообучение энкодера

`bench/finetune.py` дообучает `e5-small` на формулировках корпуса: цель
контрастная, с отрицательными примерами внутри пачки — формулировки одного
слота сходятся, разных расходятся. Проверка в четыре свёртки по сценариям,
банк для отложенных собирается тоже без них.

| свёртка | было | стало |
| --- | --- | --- |
| 1 | 74.0% | 78.6% (+4.5) |
| 2 | 75.2% | 79.1% (+3.9) |
| 3 | 77.1% | 81.0% (+3.9) |
| 4 | 78.5% | 82.6% (+4.1) |
| **итого** | **76.2%** | **80.3% (+4.1)** |

Разброс от +3.9 до +4.5 — эффект воспроизводимый. Дообученный энкодер в
одиночку обходит сплав со стоковым (78.3%).

Стоимость: полторы минуты на свёртку, **3096 МБ видеопамяти** — помещается
в 6 ГБ с запасом. Замеры на RTX 4050: пачка 128, 143 мс на шаг, эпоха 8.4 с.

#### В рантайме

`tools/train_encoder.py` обучает одну модель на всех 96 сценариях и кладёт
веса в `models/e5-small-tuned/`. 118 секунд, 448 МБ, 3.6 мс на реплику на
карте и 6.7 мс на процессоре.

Дообучение развело классы: «этаж горит» против «этаж в огне» — было 0.955,
стало 0.983; против «назовите телефон» — было 0.789, стало **0.433**.

Это меняет **механику отказа**. Раньше «не знаю» строилось на сравнении
«лучший чужой слот против лучшего своего»: шкала была сжата, и абсолютная
оценка ничего не различала. Дообученная модель кладёт всё в известные слоты,
и сравнение перестаёт срабатывать — доля отказов падает с 42% до 0.1%.
Зато теперь работает прямая отсечка: свой слот около 0.9, посторонний вопрос
около 0.4.

На слепых наборах (модель их не видела, замер честный):

| | ответ | не знаю | критичных фактов |
| --- | --- | --- | --- |
| лексика | 47.8% | 42.0% | 95.0% |
| **дообученный, отсечка 0.60** | **61.6%** | **28.9%** | **95.6%** |
| дообученный, отсечка 0.45 | 78.1% | 10.1% | 96.3% |

При меньшей доле отказов — на 14 пунктов больше ответов. Отсечка 0.45 берёт
ещё больше, но 10% отказов при том, что в слепых наборах нарочно есть
неотвечаемые вопросы, выглядит слишком доверчиво.

Запуск: `bench.run -m e5-small-tuned:torch-cuda`.

Два предупреждения. Дообучение **заучивает ошибки разметки**, а не чинит их:
контрастная цель принимает метки за истину, поэтому чистота онтологии —
условие обучения, а не следствие. И оно не влияет на laya: это отдельная
модель со своими весами.

### Понимание целиком на модели

`--nlu laya` выбрасывает банк совсем: реплика классифицируется прямо в слоты
сценария, а описанием варианта служит ответ заявителя. Новой ситуации тогда
не нужно ни одной формулировки — только факты.

Замер на 871 формулировке двенадцати сценариев (laya корпуса не видела, так
что сравнение с банком честное без вычёркиваний):

| | верно (top-1) | ложных | задержка |
| --- | --- | --- | --- |
| банк со сплавом | **78.6%** | 21.4% | 9 мс, p95 28–67 |
| только laya | 70.6% | 29.4% | 14 мс, **p95 16** |

Восемь пунктов отставания — при том, что банку они обеспечены 7461
формулировкой, написанной руками, а laya хватило метки слота. Отсюда её
место: **ситуация, для которой ещё ничего не написано**, работает сразу.

Подмешивать laya в основной путь не надо, это проверено: любой вес ухудшает
результат (0.2 → 76.7%, 0.5 → 74.3%). С лексикой и векторами сплав удался,
потому что они ошибаются на разном; здесь laya просто слабее.

Банк умеет уйти на 2.6% ложных, сохранив 46.6% верных. Laya ниже ~21% не
опускается ни при каком пороге — для тренажёра это существенно, ложный факт
попадает обучающемуся в карточку.

Известный дефект режима: `caller.phone` стягивает на себя чужие вопросы,
включая «что случилось». Не зависит от того, как описан вариант, — проверены
три способа.

### Про арбитра

Серую зону закрывает не языковая модель с генерацией, а типизированное
решение за один проход. Замер на двенадцати размеченных случаях
с **перемешанными позициями вариантов**:

| арбитр | верно | отказы | CPU | RTX 4050 |
| --- | --- | --- | --- | --- |
| Qwen3-1.7B, вывод зажат грамматикой | 2–3 из 10 | 0 | 135 мс | 66 мс |
| Qwen3-1.7B с рассуждениями | 5–6 из 10 | — | 12 150 мс | 3 496 мс |
| **laya-multilingual** | **8 из 12** | **2 из 4** | 144 мс | **14 мс** |

Qwen не годится по двум причинам сразу. Два-три из десяти при шести
вариантах — случайный тык, а единственный режим, где она соображает, стоит
секунды. И главное: она **ни разу не выбрала «ни о чём»**. Для тренажёра это
решающее свойство — ложный факт попадает обучающемуся в карточку, и он будет
уверен, что записал верно.

Laya выбирает из вариантов одним проходом, без генерации, отдаёт вероятности
по всем вариантам и умеет отказываться. Реплики оператора кириллицей,
поэтому берётся мультиязычный чекпоинт: английский на нечитаемом для него
письме даёт ноль при высокой уверенности, и отсечь это по уверенности нельзя.

Мерить такое надо с перемешанными вариантами. Первый замер Qwen показал
5 из 8 и оказался недействительным: ожидаемый слот стоял первым, а модель
отвечала «1» независимо от вопроса.

Laya на GPU требует собранного модуля Triton, а тот — заголовков Python:

```bash
sudo apt install python3.12-dev
```

#### Чего с laya делать не надо

Проверено и отвергнуто, чтобы не возвращаться.

**Подмешивать её оценку к банку.** Любой вес ухудшает: 78.6% → 76.7% при 0.2,
→ 74.3% при 0.5. Ошибки не дополняют друг друга, она просто слабее.

Зато работает обратное — отдать ей **только то, где банк слаб**. Флаг
`thin_rescue`: арбитр выбирает среди слотов сценария, у которых меньше 40
формулировок, и не вправе спорить с населённым слотом.

```
банк как есть                            81.1%
+ laya на бедных слотах (порог 0.80)     83.0%   (+1.9)
```

Когда laya ограничена так, она права в 71–90% вмешательств против своих же
67% в одиночку. Ограничение сделало её точнее.

Замерено на стоковом банке. Дообучение могло частично закрыть провал на
бедных слотах — тогда прибавка окажется меньше, и проверять это надо по
свёрткам, потому что нынешние веса видели весь корпус.

**Давать ей контекст.** Замер на 871 формулировке:

```
только вопрос         верно 67.4%   магнит caller.phone:  89
+ описание ситуации   верно 49.6%   магнит caller.phone: 255
+ ситуация и роль     верно 51.9%   магнит caller.phone: 163
```

Минус восемнадцать пунктов. Laya кодирует состояние целиком и сравнивает его
с описаниями вариантов, поэтому полторы сотни символов про ситуацию топят
короткий вопрос: модель начинает выбирать вариант, похожий на ситуацию, а не
на вопрос. Вход у неё должен быть минимальным — обратно тому, что помогает
генеративным моделям.

**Дообучать.** Нельзя: в пакете только вывод, обучающего кода нет, веса
закрыты.

#### Сколько он даёт на слепых наборах

```
без арбитра            47.8% ответов, 95.0% критичных фактов
арбитр, узкая зона     48.3%,         95.4%   (130 вызовов на 6168 реплик)
арбитр, зона до нуля   48.5%,         95.4%   (203 вызова)
```

Прибавка мала, и расширение серой зоны её почти не меняет. Причина не в
арбитре: **41% «не знаю» приходят не из серой зоны, а из ветки «спросили о
чужом слоте»**, которая срабатывает раньше и возвращает ответ, не доходя до
порогов. Система эти реплики спорными не считает, выбирать там не из чего.

Настоящая серая зона — двести случаев, где банк колеблется между своими
слотами. Арбитр отвечает на 86 из них и отказывается на 117, сбоев ноль.

По умолчанию выключен: полпроцента ответов не стоят того, чтобы рантайм
получил зависимость от CUDA и 1.6 ГБ видеопамяти. Включается флагом
`--arbiter laya`.

Текст ответа всегда берётся из билета. Модель работает только
классификатором и физически не может ничего сочинить.

## Запуск

```bash
python3 -m dispatcher.cli chat bilet04_call01           # диалог руками
python3 -m dispatcher.cli chat bilet04_call01 --nlu laya --device cuda
python3 -m dispatcher.cli chat bilet04_call01 -v        # с разбором каждого хода
python3 -m dispatcher.cli replay bilet04_call01 -f examples/dialog.txt --stream
python3 -m dispatcher.cli slots bilet04_call01          # что знает заявитель
python3 -m dispatcher.cli lint bilet04_call01           # дотянется ли корпус
python3 -m dispatcher.cli suggest "какой этаж горит"    # куда положить новый факт
```

Флаг `--fresh` вычёркивает формулировки самого сценария: так он выглядит для
системы, которая его никогда не видела. Именно в этом режиме надо смотреть
на новую ситуацию.

## Измерения

Разметка для них не нужна: эталон известен заранее — это слот факта,
которому принадлежит формулировка.

```bash
python3 -m bench.loo        # сценарий против банка, который его не видел
python3 -m bench.run        # сквозной прогон слепых наборов
python3 -m bench.encoders   # сравнение энкодеров и подбор веса сплава
```

`bench.loo` меряет ровно то, что случится с новой ситуацией пользователя.
`bench.run` разбирает исходы: ответ, «не знаю», «не расслышала» и «мимо» —
последнее и надо уменьшать.

## Формат сценария

Одни английские идентификаторы, русский — только в текстах для людей
(`questions`, `answers`, `opening`, значения `meta`). Факт: `id`, `slot`,
`numbers` (если есть числа), `questions` (можно не писать — их даст корпус),
`answers` (`plain` обязателен, остальные по необходимости), `disclosure`,
`requires`. Id факта — это слот; если слот делят несколько фактов, первый
забирает голый слот, остальные — `слот#2`, `слот#3`:

```json
{
 "id": "bilet04_call01",
 "meta": {"situation": "...", "address_ref": "Москва, ул. Грина, дом 11"},
 "persona": {"profile": "calm", "opening": "Алло, тут балкон горит!"},
 "critical": ["addr.street", "fire.floor"],
 "facts": [
  {"id": "fire.floor", "slot": "fire.floor", "numbers": [13],
   "questions": ["на каком этаже горит"],
   "answers": {"plain": "На тринадцатом этаже, балкон весь в огне."}},
  {"id": "addr.landmark", "slot": "addr.landmark",
   "requires": ["addr.street"],
   "answers": {"plain": "В этом доме библиотека."}}
 ]
}
```

Старые файлы с `key`/`group`/`value_numbers` читаются как раньше, перевести
их помогает `python3 tools/migrate_scenario.py`. Алиасы русских ключей
в `slots.yaml` оставлены ради этой совместимости.

## Как завести новую ситуацию

1. Написать факты: id, слот, текст ответа, стили `short`/`confirm`/`correct`,
   `disclosure` и список критичных. Формулировки вопросов не писать.
2. `cli suggest` подскажет слот, если непонятно, куда класть факт.
3. `cli lint` покажет факты, до которых корпус не дотягивается, — только им
   и нужно дописать несколько формулировок.
4. `bench.run` покажет, не просела ли точность на старых сценариях.

Уточнения «в скобках» из билета помечаются `"disclosure": "on_request"`:
заявитель называет их только по прямому вопросу, и обучающийся обязан
догадаться спросить. В корпусе таких 27 фактов в 23 сценариях.

## Установка

```bash
python3 -m venv .venv
.venv/bin/pip install pymorphy3==2.0.6 razdel==0.5.0 numpy PyYAML "setuptools<81" pytest
```

Лексический каскад работает на этом и больше ничего не требует.
Векторный слой добавляется отдельно:

```bash
.venv/bin/pip install onnxruntime tokenizers huggingface_hub   # CPU
.venv/bin/pip install torch transformers                       # и/или CUDA
.venv/bin/pip install laya                                     # арбитр серой зоны
```

Модели кладутся в `models/<имя>/` и оттуда берутся без обращения к Хабу —
рантайму сеть не нужна. Скачать всё разом: `bash tools/fetch_models.sh`.
