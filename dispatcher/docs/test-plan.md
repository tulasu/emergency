# Шаг 8. Тестирование без SIP — план

Статус: только план, кода нет.
Граница шага: проверяем всё, что можно проверить без Asterisk/SIP/RTP.
Реальные STT/TTS и `sipp`-прогон — приёмка шага 3 (`docs/sip-plan.md`), не здесь.

Идея в одной строке: эталон — `cli replay`, всё остальное обязано
совпадать с ним посимвольно; цифры точности — `bench/run.py` до выноса в сервис.

## 1. `replay --stream` как контракт-тест partial/final

Что уже есть: `Session.on_partial/on_final` и инвариант
«текстовый вход = потоковый» (`dispatcher/session.py`,
`tests/test_session.py::test_stream_matches_text`).
`cli replay --stream` эмулирует STT ровно так же:
`for i in range(6, len(line), 5): on_partial(line[:i])` + `on_final(line)`
(`dispatcher/cli.py::cmd_replay`).

Процедура:

1. Фиксируем пары прогонов на одних входах:
   `replay <sid> -f <file>` vs `replay <sid> -f <file> --stream`.
   Входы: `examples/dialog.txt` + слепые фразы `data/blind/blind_<sid>*.txt`
   (те же 6011 реплик, что ест `bench/run.py`).
2. Сравниваем stdout посимвольно (тексты `заявитель>` и сводку `_summary`).
   Латентность (`медиана/p95`) из сравнения исключить — только тексты и счётчики.
3. Краевые случаи (уже частично в `test_session.py`, прогнать через CLI тоже):
   - `on_final` без предварительных partial — тот же ответ, что с ними;
   - partial `<6 символов` и дубликаты — хода нет, `turns` пуст;
   - `cancel()` после partial снимает спекуляцию, повторный `say` даёт тот же ответ;
   - префикс-лоовушка: partial одного вопроса + final другого
     (спекуляция обязана не применяться — несовпадение `_draft_text`).

Приёмка: `replay` и `replay --stream` совпадают посимвольно
на всех входах п. 1; расхождение = баг ядра/транспорта, не «особенность STT».

## 2. E2E Go ↔ Python-gRPC на записанном wav, VAD/STT мокнуты

Проверяем связку целиком, но без сети и распознавания:
аудио детерминировано, «распознавание» — подставной transcript.

Фикстуры (записать один раз, хранить рядом с тестами):

- `tests/fixtures/<sid>.wav` — начитанный `examples/dialog.txt`
  (один голос, паузы между репликами; alaw/16k — как будущий RTP).
- `tests/fixtures/<sid>.json` — sidecar: для каждой реплики
  `[{t_start, partials: [...], final: "..."}]` — скрипт того,
  что «услышал» мок-STT и когда сработал мок-VAD.

Компоненты теста:

- Мок-VAD: режет wav на сегменты по sidecar-меткам
  (никакой энергии/порогов — детерминизм важнее реализма).
- Мок-STT: на сегменте отдаёт `partials` по таймеру, по концу сегмента — `final`.
- Go-клиент (будущий медиа-сервис): `Open(scenario_id)` → сверка `opening()`
  с `cli chat <sid>` → цикл `Partial* → Final → Reply` → `Close`.
  Прото — `docs/session-contract.md` п. 2
  (`Open/Partial/Final/Cancel/Close`, `session_id = call_id`).
- Python-сервер: боевая сборка `Open` (синглтоны `Ontology/LexicalBank/Encoder/
  VectorBank` + `Cascade`+`Session` per-call, как `cli._build`), не упрощённая.

Сверки:

1. Каждый `Reply.text` из gRPC == соответствующая строка `cli replay -f transcript`.
2. Ошибки контракта: неизвестный `scenario_id` → `NOT_FOUND`;
   метод по закрытому/неизвестному `session_id` → `NOT_FOUND`;
   повторный `Close` — no-op; `Cancel` без partial — безопасен,
   после partial возвращает `audio_id` текущей реплики.
3. Порядок: partial/final одного `session_id` строго последовательно
   (очередь на сессию — требование контракта, п. 4 `session-contract.md`).

Приёмка: зелёный прогон на 1–2 сценариях (`bilet04_call01` + ещё один);
расхождение Reply с `cli replay` = баг gRPC-обвязки, не ядра.

## 3. Регрессия точности после выноса в сервис (`bench/run.py`)

`bench/run.py` считает разбор по исходам
(`ответ / не знаю / не расслышала / мимо`), долю критичных фактов
и `p50/p95` понимания. Это золотой стандарт — снимаем слепок до выноса.

Процедура:

1. До выноса: `python3 -m bench.run` (и каждая используемая `-m <модель:бэкенд>`
   / `--arbiter laya` комбинация) → сохранить stdout целиком как golden-файл
   (например `bench/golden/<конфиг>.txt`).
2. После выноса: тот же корпус `data/blind` прогнать через сервисную сборку —
   через gRPC-цикл `Open → Final* → Close` (Partial слать не обязательно:
   контракт гарантирует эквивалентность, см. п. 1) либо in-process
   против серверного `_build`. Seed рендера фиксировать (`Session.open(..., seed=…)`),
   иначе тексты поплывут не из-за регрессии.
3. Сравнить исходы с golden: счётчики `ответ/не знаю/не расслышала/мимо`
   и `критичных фактов добыто` — строго равны; `p50/p95` — только sanity-граница
   (не выросли в разы), побайтовое равенство латентности не требовать.

Приёмка: `мимо` не выросло ни на одну реплику, критичные не просели;
любой дельта-разбор — через `bench/run.py --show` до мержа.

## Порядок внедрения

3. П. 2: wav + sidecar + мок-VAD/STT + e2e Go↔Python.
4. П. 3.2–3.3 после выноса: регрессия против golden.
