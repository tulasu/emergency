# Заявитель — движок диалога для тренажёра оператора 112

Пять этапов, каждый в своём файле, каждый тестируется отдельно.

```
caller/contracts.py   типы, которыми этапы обмениваются
caller/morph.py       морфология: леммы, токены, числительные
caller/understand.py  этап 2 — реплика превращается в ключи фактов
caller/decide.py      этап 3 — поведение заявителя
caller/speak.py       этап 4 — формулировка и ссылка на аудио
caller/score.py       этап 5 — журнал и разбор занятия
caller/engine.py      сборка
caller/cli.py         запуск
scenarios/*.json      данные: факты, персона, реплики
```

Поток одного хода:

```
реплика → Understanding{keys, act} → Decision{reveal, style, mood} → Reply{text, audio}
```

Этап 3 не знает, как распознали реплику. Этап 2 не знает текстов ответов.
Поэтому понимание меняется без единой правки в поведении, а поведение
настраивается без правок в распознавании.

## Установка

```bash
pip install pymorphy3 razdel "setuptools<81"
```

`setuptools<81` обязателен: словари pymorphy тянут `pkg_resources`, который
в новых версиях удалён. Без пина получите падение импорта на чужой машине.

## Запуск

Диалог руками:

```bash
python3 -m caller.cli chat scenarios/bilet04_call01.json
```

Прогон готового диалога из файла:

```bash
python3 -m caller.cli run scenarios/bilet04_call01.json -f examples/dialog.txt
```

Оценка покрытия на слепом наборе реплик:

```bash
python3 -m caller.cli eval scenarios/bilet04_call01.json -f examples/blind_bilet04.txt
```

Понимание переключается флагом `--nlu`:

```bash
python3 -m caller.cli chat scenarios/bilet04_call01.json --nlu lexical
python3 -m caller.cli chat scenarios/bilet04_call01.json --nlu hybrid
export ANTHROPIC_API_KEY=...
python3 -m caller.cli chat scenarios/bilet04_call01.json --nlu llm --profile normal
```

- `lexical` — офлайн, margin + `Profile.min_confidence`; при сомнении «не знаю».
- `hybrid` — lexical; на ambiguous / эллипсис с контекстом / reject+context —
  LM Studio (`http://127.0.0.1:1234`, ~200 мс). Удачные формулировки копятся в
  `cache/paraphrases/{scenario_id}.json` (JSON преподавателя не меняем).
- `llm` — Anthropic-классификатор; без ключа молча lexical.

На каждом ходе CLI печатает строку timing (`--timing` / `--no-timing`):

```text
[timing total=187ms understand=172 decide=0 speak=0 | lex=4 llm=timeout:168 path=lexical]
```

Без ключа режим `llm` молча работает как `lexical`, демо не встаёт.

## Способы понимать

`lexical` — пересечение лемм + IDF + runtime-paraphrases из кэша. Ключ только при
`score ≥ min_confidence` и margin; иначе «не знаю».

`hybrid` — то же, плюс локальный классификатор с диалоговым контекстом
(последние реплики и факты). Текст ответа всегда из сценария.

`llm` — облачный классификатор ключей с кэшем в `cache/understand.json`.

## Что делает заявителя живым

Этап «решение» держит состояние: что уже рассказано, сколько ходов оператор
топчется, какое настроение.

- Вопрос не про то, что заявитель может знать → «не знаю», а не «повторите».
  Это главное отличие от прошлой версии: раньше система упиралась в стену
  на каждом вопросе вне сценария.
- Короткая искажённая реплика → «не расслышала».
- Три и больше вопросов разом → отвечает на два и просит не частить.
- Оператор назвал неверное число → заявитель поправляет.
- Повторный вопрос → ответ суше.
- Настроение ползёт вверх, если оператор буксует, и падает после
  «помощь выехала». Потолок задаётся профилем.
- Критичный факт долго не спрашивают → заявитель напоминает сам, и это
  записывается обучающемуся в минус.

Профили: `calm` (по умолчанию), `normal`, `hard`. Меняют скорость роста
настроения, терпение и число фактов за ход.

## Оценка

Считается не то, сколько реплик система поняла, а сколько **обязательных**
фактов обучающийся сумел добыть. Список обязательных задаётся в сценарии
полем `critical`.

«Не знаю» и «повторите» обучающемуся не в минус: заявитель имеет право
не знать. Штрафуется другое — напоминания заявителя, неверно записанные
значения, заваливание вопросами.

## Как добавить сценарий

Скопируйте `scenarios/bilet04_call01.json` и замените данные. Обязательные
поля факта: `key`, `questions` (8–12 способов спросить, включая односложные),
`answers.plain`. Остальное достраивается.

Порядок работы: написали сценарий → `eval` на слепом наборе → дописали
вопросы по списку «без ответа по существу» → снова `eval`, но **на другом
наборе**. Мерить на том же файле, по которому дополняли, бессмысленно:
проверено, цифра завышается вдвое.
